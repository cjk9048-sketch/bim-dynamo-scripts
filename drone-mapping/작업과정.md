## 처리 차례 (`roadview/mapping.py` main)

| 왜곡 펴기 | COLMAP image_undistorter | 질감 사진 1320/2640/5280 px | dense/sparse |
| 점구름 준비 | OpenMVS InterfaceCOLMAP | | scene.mvs |
| 점구름 | OpenMVS DensifyPointCloud (**CPU**) | 깊이 지도 폭: 측량용 660/1320/2640 · 3D 만 660/660/1320 px | scene_cpu.ply + params.dense |
| 3D 면 | OpenMVS ReconstructMesh (CPU) | 세모 한도 100만/300만/600만 | scene_cpu_mesh.ply + params.faces |

| 측량 점구름 | DensifyPointCloud → scene_srv | 3D 만 만든 프로젝트에 측량 결과물을 더할 때만 | scene_srv.ply |
| 결과물 | Python (numpy · OpenCV · Pillow · pyproj) | 정사 · DSM · DTM · LandXML · LAS · 보기 조각 | 늘 다시 (2~3분) |

- 카메라 묶기: 사진마다 XMP(카메라 이름 · 크기 · 초점)로 묶어 **가장 많은 카메라만** 씀 (광각 · 망원 섞이면 뺌 · 기록에 남김).
- 사진 이름 목록(`--names`) = 매핑 화면에서 고른 사진 · 결과 폴더 `work\pick.txt`.
- 진행 = «@진행 퍼센트 남은초 글» 줄 (앱 Job 이 읽음) · 단계 무게는 실측 비율 · 안 할 단계는 0.

### 단계 다시 쓰기 (`work\stages.json`)
- `sig` = 차례 판(PIPELINE_VERSION) · 품질 · 사진 이름 · 처음 내부표정 (+ 카메라 풀기 방식을 굳이 고르면). 바뀌면 처음부터.
- `done` = 끝난 단계 · `drop_from(단계)` = 그 단계와 뒤를 다시 (측량 점구름은 점구름 · 그 앞이 바뀔 때만 버림).
- `params` = {점구름 해상도 · 세모 한도} — 1.0.14 이전 프로젝트는 측량용 해상도로 봄.
- `stale_outputs` = 처음부터 다시 시작한 판 표시 → 결과물을 새로 쓸 때까지 옛 결과물을 믿지 않음 (그 판이 중간에 끊겨도).
- 좌표계가 바뀌면 옛 결과물 · 3D · 관로를 지우고 원점을 새로 (관로는 다시 넣기).
- 끝나면 무거운 중간 자료(깊이 지도 · 왜곡 편 사진) 지움 → 다음에 필요하면 `ensure_images()` 가 사진만 다시 폄 (뒤 단계는 안 지움).

### 좌표 · 높이
- M4E 사진 XMP 위치 = RTK 고정해(RtkFlag 50) · AbsoluteAltitude = **타원체고**.
- 카메라 중심 ↔ RTK 위치(ECEF) 닮음 맞춤(Umeyama) → 모델 좌표를 ECEF 로 → **위경도 · 타원체고(4979)로 바꾼 뒤** 평면(고른 CRS) · 높이(EGM2008 3855) 따로.
- RTK 어긋남 RMS ≈ 0.13 m (GCP 없이). 지오이드 격자를 못 받으면 멈춤 (타원체고를 말없이 쓰지 않음 — 검토로 확인).

### DTM (땅만)
칸(0.5 m)마다 가장 낮은 점 → 이웃 가운데값보다 0.5 m 낮은 잡음 칸 빼기 → 점진형 형태학 필터(OpenCV 열림 · 창 5~65칸 · 상한 33 m · 기울기 0.25 · 높이 0.3 ~ 2.5 m) → 땅 칸만 → 빈 곳 pull-push + 400번 조화 보간.

## 함정 · 배운 것

| 증상 | 원인 → 고침 |
|---|---|
| OpenMVS CUDA 판 «named symbol not found» | RTX 50(연산 능력 12.0) 커널 없음 → CPU (`--cuda-device -2`) |
| 일반 zip OpenMVS 가 바로 종료코드 1 · 기록 없음 | 그 판엔 `--cuda-device` 옵션이 없음 → 도움말로 확인하고 붙임 (`mvs_cuda_opt`) |
| COLMAP 점 깊이(GPU) 80장 51분 | 이웃 사진 읽기 병목 → OpenMVS CPU (13배 빠름) |
| OpenMVS 질감 좌표가 그림과 어긋남 · 800만 세모에서 죽음 | → COLMAP mesh_texturer (질감 좌표 99.9 % · v 뒤집기) |
| DSM 이 DEM 보다 24 m 높음 | 4978 → 5186+3855 한 번에 바꾸면 지오이드를 건너뜀 → 위경도 · 타원체고 거쳐 평면 · 높이 따로 |

## 내가 정한 것 (이유)

- **설계서의 C# WPF + CesiumJS + ODM 대신 지금 틀(Python · WebView2 · 자체 WebGL · COLMAP + OpenMVS) 유지**: 이미 드론 로드뷰 안에서 돌아가고, 관로 얹기 · 공유를 그대로 씀. 설계서에서는 카메라 묶기 · 정보.txt · 단계 다시 쓰기 · DTM · 검사점 · 좌표계를 가져옴.
- **점구름 · 면 = CPU**: OpenMVS CUDA 판이 RTX 50 미지원.
- **50장 이상 = 전역 카메라 풀기**: 394장 26 → 10~15분 · 정확도 같음 · 모자라면 한 장씩으로 다시.
- **DJI DewarpData 안 씀**: 처음 내부표정은 XMP 초점 · 주점, 왜곡은 COLMAP 이 풂 (RTK 어긋남 0.13 m 로 충분).
- **질감 조각 한 변 8192**: 오래된 내장 그래픽 · 시험 렌더러 한도.
- **DTM = 점진형 형태학 필터 (OpenCV)**: 설치본에 있는 것으로 (PDAL 같은 새 의존성 없음). 사진만으로는 숲 밑 땅을 모름 → 메운 곳 따로 표시.
- **검사점 = 확인만**: GCP 로 모델을 고치지 않음 (RTK 로 이미 0.13 m · 검사점과 GCP 는 따로).
- **좌표계 기본 = 5186**: 회사 도면 · 그레이딩 · 로드뷰와 같음.
- **만들 것 기본 = 3D 만 · 3D 만이면 점구름 한 단계 덜 촘촘**: JACK «주로 3D 매핑 · 빠르게» · 겉모습은 질감이 정함 · 측량용 결과물은 늘 측량용 해상도.
- **LAS 도 넣음 (기본 꺼짐)**: 처음 인터뷰엔 없었지만 JACK «포인트클라우드» 말씀.
- **DTM 창 상한 33 m**: 넓은 성토 도로 · 둑이 «땅 아님»으로 깎이지 않게 (검토).
