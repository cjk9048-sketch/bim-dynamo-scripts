# Civil 3D 횡단도 수량표 자동화 애드인 설계 검토

## 1. 검토 목적

현재 개발 중인 Civil 3D 애드인의 목표는 다음과 같다.

- 원지반 Surface 생성
- 터파기 모델 생성
- 계획지반 Surface 생성
- 횡단도 생성
- 기존 2D 설계도면과 유사한 형태의 횡단도 및 수량표 자동 작성
- 측점별 터파기, 되메우기, 성토, 면고르기 등의 수량 자동 산출

특히 기존 2D 도면처럼 횡단도에 다음과 같은 수량표를 자동으로 생성하고, 각 측점의 계산값을 자동 입력하는 것이 목표이다.

예시 항목:

- 터파기 (5.0m 이하)
  - 육상 / 토사
  - 육상 / 토사
  - 용수 / 토사
  - 용수 / 풍화암
- 터파기 (5.0m 이상)
- 되메우기
- 성토
- 구조물 피복토
- 바닥면 고르기
- 면고르기
- 비탈면 보호공
- 표토제거
- 벌개제근
- 총대기

---

# 2. 결론

Civil 3D에는 QTO(Quantity Takeoff) 및 Material 관련 .NET API가 공개되어 있으므로 **재료정의 및 수량산출 과정을 애드인에서 자동화하는 것이 가능하다.**

대표적으로 활용할 수 있는 API 객체는 다음과 같다.

- `QuantityTakeoffCriteria`
- `QuantityTakeoffCriteriaCollection`
- `QTOMaterialListCollection`
- `QTOMaterial`
- `QTOSubcriteria`
- `QTOMaterialItem`
- `SectionViewQuantityTakeoffTable`

따라서 사용자가 Civil 3D 화면에서 수동으로 QTO Criteria와 Material을 만드는 방식이 아니라, 애드인이 프로젝트의 Surface 및 Sample Line Group을 분석한 후 필요한 QTO 구조를 자동 생성하도록 구현할 수 있다.

---

# 3. 기본적인 자동화 구조

권장되는 전체 흐름은 다음과 같다.

```text
[횡단 수량표 생성]
        ↓
현재 Sample Line Group 확인
        ↓
원지반 Surface 확인
        ↓
계획지반 Surface 확인
        ↓
터파기 Surface 확인
        ↓
QTO Criteria 확인
        ↓
없으면 자동 생성
        ↓
Material 자동 생성
        ↓
Surface / Corridor Shape 자동 Mapping
        ↓
Material List 생성
        ↓
수량 계산
        ↓
측점별 수량 데이터 추출
        ↓
회사 표준 2D 수량표 생성
```

즉, **QTO 설정 자체도 애드인에서 자동화할 수 있다.**

---

# 4. QTO를 이용하는 방법

Civil 3D의 QTO 구조를 이용하면 다음과 같은 공종을 비교적 자연스럽게 처리할 수 있다.

## QTO에 적합한 항목

- 터파기
- 성토
- 되메우기
- 절토
- 구조물 피복토
- 기존면과 계획면 사이의 체적
- Corridor Shape 기반 수량

예를 들어 다음과 같은 Material을 애드인이 자동 생성할 수 있다.

```text
터파기_5m이하_토사
터파기_5m이하_풍화암
터파기_5m이상_토사
터파기_5m이상_풍화암
되메우기_토사
성토_토사
```

그리고 각각에 필요한 Surface 또는 Corridor Shape를 자동으로 연결한다.

---

# 5. QTO Criteria 자동 생성

프로젝트마다 사용자가 직접 Criteria를 만들게 하지 않고 애드인이 다음과 같이 처리할 수 있다.

```text
[프로젝트 설정]

원지반 Surface : EG
계획지반 Surface : FG
터파기 Surface : EXC
토사 Surface : SOIL
풍화암 Surface : WR

터파기 기준 깊이 : 5.0m
```

애드인은 다음 순서로 동작한다.

```text
QTO Criteria 존재 여부 확인
        ↓
존재하면 기존 Criteria 사용
        ↓
없으면 Criteria 생성
        ↓
Material 생성
        ↓
Subcriteria 생성
        ↓
Surface Mapping
        ↓
Material List 생성
```

또한 회사 표준 Criteria를 미리 만들어 놓고 프로젝트에서는 필요한 Surface만 Mapping하는 방식도 가능하다.

---

# 6. Civil 3D 기본 수량표를 그대로 사용하지 않는 것을 권장

Civil 3D에는 `SectionViewQuantityTakeoffTable`과 같은 수량표 관련 객체가 있으므로 기본 수량표를 횡단도에 삽입할 수도 있다.

하지만 현재 목표가 기존 2D 설계도면과 동일하거나 유사한 **회사 표준 도면 양식**이라면, Civil 3D 기본 수량표에 모든 표현을 맡기는 것은 권장하지 않는다.

기존 도면에는 다음과 같은 표현이 필요할 수 있다.

- 병합 셀
- 행 높이
- 열 너비
- 선 색상
- 선 두께
- 문자 높이
- 문자 정렬
- Layer
- 특정 공종 순서
- 회사 표준 문자 스타일
- 특정 블록 및 도면 표현

따라서 다음 구조를 추천한다.

```text
QTO
 ↓
수량 계산
 ↓
애드인 내부 수량 데이터
 ↓
AutoCAD Table 생성
 ↓
회사 표준 횡단도 수량표
```

즉,

> **QTO는 계산 엔진으로 사용하고, 최종 도면 표는 애드인이 직접 생성한다.**

---

# 7. QTO와 자체 계산엔진을 혼합하는 방법

모든 공종을 QTO로 처리할 필요는 없다.

## QTO가 적합한 공종

```text
터파기
성토
되메우기
구조물 피복토
절토
```

## 자체 Geometry 계산이 더 적합할 수 있는 공종

```text
표토제거
벌개제근
바닥면 고르기
면고르기
비탈면 보호공
```

예를 들어 표토제거는 단순히

```text
표토제거 깊이 × 대상 폭
```

으로 계산할 수 있다.

벌개제근은

```text
대상 면적
```

으로 계산할 수 있다.

바닥면 고르기는

```text
터파기 바닥 폭 × 해당 구간 길이
```

등으로 계산할 수 있다.

비탈면 보호공은 횡단면의 실제 경사 길이를 이용하여 면적을 계산하는 방식이 더 직접적일 수 있다.

---

# 8. 추천하는 전체 시스템 구조

현재 개발 중인 애드인을 다음과 같이 분리하는 것을 권장한다.

```text
                    Civil 3D 애드인
                          │
        ┌─────────────────┼─────────────────┐
        ↓                 ↓                 ↓
   모델 생성부        수량 계산부        도면 생성부
        │                 │                 │
     Surface          QTO Engine       Section View
     Corridor         Custom Engine    Label
     Sample Line      Classification   Table
        │                 │                 │
        └─────────────────┼─────────────────┘
                          ↓
                    표준 수량 데이터
                          │
             ┌────────────┴────────────┐
             ↓                         ↓
          횡단도 표                   집계
       (AutoCAD TABLE)              (Excel)
```

이 구조의 장점은 모델 생성, 수량 계산, 도면 표현을 서로 독립적으로 수정할 수 있다는 것이다.

---

# 9. 자체 수량 데이터 모델을 두는 것을 권장

QTO 객체와 최종 도면 표를 직접 1:1로 연결하지 않는 것이 좋다.

애드인 내부에 다음과 같은 자체 데이터 구조를 두는 것을 권장한다.

```csharp
class QuantityItem
{
    string Code;
    string Name;
    string Category;
    string Material;
    string Unit;
    double Quantity;
    string CalculationMethod;
}
```

구조적으로는 다음과 같다.

```text
Civil 3D QTO
      ↓
QuantityItem

자체 Geometry 계산
      ↓
QuantityItem

QuantityItem
      ↓
DrawingTableRenderer
      ↓
AutoCAD 2D TABLE
```

이렇게 하면 QTO에서 계산한 값과 자체 계산한 값을 동일한 방식으로 도면에 출력할 수 있다.

또한 발주처나 회사에서 표 양식을 변경하더라도 계산엔진은 그대로 두고 도면 Renderer만 수정할 수 있다.

---

# 10. 5m 이하 / 5m 이상 처리 시 주의점

현재 표에서 가장 중요한 계산 규칙 중 하나가 `터파기 5.0m 이하`와 `터파기 5.0m 이상`의 구분이다.

단순히 Material을 두 개 만드는 것만으로 해결되지 않을 수 있다.

횡단에서 깊이가 구간별로 다르면 터파기 영역 자체를 깊이 기준으로 분할해야 한다.

```text
터파기 영역
      ↓
각 지점의 터파기 깊이 계산
      ↓
5.0m 기준선 생성
      ↓
5m 이하 영역
5m 이상 영역
      ↓
토사 / 풍화암 등과 교차
      ↓
각 공종별 면적 및 체적 계산
```

따라서 이 부분은 QTO 기능만으로 처리하기보다는 **애드인 자체 Geometry 계산 로직을 함께 사용하는 혼합 방식**이 안정적이다.

---

# 11. 토사 / 풍화암 / 연암 등의 지층 구분

지층별 수량을 산출하려면 횡단면에서 지층 경계를 구할 수 있어야 한다.

예를 들어:

```text
원지반
────────────────────

토사
~~~~~~~~~~~~~~~~~~~~

풍화암
--------------------

연암
////////////////////
```

터파기 영역과 각 지층 영역을 교차시키면 다음과 같이 계산할 수 있다.

```text
터파기 폴리곤
      ∩
토사 영역
      ↓
토사 터파기

터파기 폴리곤
      ∩
풍화암 영역
      ↓
풍화암 터파기
```

Civil 3D QTO의 Surface 조건을 이용하면 일부 영역은 QTO에서 처리할 수 있다.

다만 복잡한 지층 구분이나 설계 기준에 따른 세부 분류가 필요한 경우에는 자체 Geometry Engine을 두는 것이 좋다.

---

# 12. 권장하는 표 생성 방식

최종 도면 표는 AutoCAD `AcDbTable` 기반으로 생성하는 것을 추천한다.

애드인이 다음을 직접 제어할 수 있다.

- 행/열 수
- 셀 병합
- 행 높이
- 열 너비
- 문자 높이
- 문자 정렬
- 선 색상
- 선 두께
- Layer
- Table Style
- 문자 스타일
- 공종 표시 순서

따라서 기존 2D 도면의 표 양식을 최대한 동일하게 재현할 수 있다.

---

# 13. 회사 표준 QTO를 재사용하는 방법

매 프로젝트마다 QTO Criteria를 새로 만들지 않고 회사 표준으로 관리하는 것도 가능하다.

예:

```text
DH_관로횡단_QTO
```

애드인이 실행되면:

```text
Criteria 존재?
      │
 ┌────┴────┐
 │         │
Yes       No
 │         │
기존 사용   자동 생성
```

그리고 프로젝트별 Surface 이름만 Mapping한다.

예:

```text
원지반 → EG
계획지반 → FG
터파기 → EXC
토사 → SOIL
풍화암 → WR
```

이렇게 하면 프로젝트가 달라져도 동일한 수량 산출 규칙을 사용할 수 있다.

---

# 14. 최종 권장 구조

현재 개발 중인 애드인의 목표를 고려하면 다음 구조가 가장 적합하다.

```text
                    [Civil 3D 모델]
                           │
             ┌─────────────┴─────────────┐
             │                           │
             ↓                           ↓
       [QTO 계산 대상]               [직접 계산 대상]
             │                           │
       터파기/성토/되메우기          표토제거
       구조물 피복토                벌개제근
       절토                         면고르기
                                    비탈면 보호공
                                    바닥면 고르기
             │                           │
             └─────────────┬─────────────┘
                           ↓
                     [수량 데이터]
                           ↓
                   [표준 수량 모델]
                           │
             ┌─────────────┴─────────────┐
             ↓                           ↓
       횡단도 수량표                  수량 집계
        AutoCAD TABLE                   Excel
```

| 검토 항목 | 판단 |
|---|---|
| Civil 3D Material/QTO API 공개 여부 | 가능 |
| QTO Criteria 자동 생성 | 가능 |
| Material 자동 생성 | 가능 |
| Sample Line Group Material List 자동 생성 | 가능 |
| Surface/Corridor Shape 자동 Mapping | 가능 |
| QTO 계산 결과 활용 | 가능 |
| Civil 3D 기본 수량표 사용 | 가능하지만 비추천 |
| 회사 표준 2D 표 직접 생성 | 가능 |
| QTO 없이 자체 계산 | 가능 |
| 모든 공종을 QTO로 처리 | 비추천 |
| 추천 방식 | **QTO + 자체 Geometry 계산 혼합** |

# 16. 다음 개발 단계에서 먼저 정의할 사항

실제 구현에 들어가기 전에 다음 항목을 확정하는 것이 좋다.

1. 각 수량표 행이 면적인지 체적인지
2. 각 공종이 어떤 Surface 또는 Geometry를 기준으로 하는지
3. 터파기 5m 이하 / 이상을 어떤 기준으로 판정하는지
4. 토사 / 풍화암 / 연암 경계를 어디에서 가져오는지
5. 용수 여부를 어떤 데이터로 판정하는지
6. 각 측점에서 표에 들어가는 값의 단위
7. 좌측/우측 수량을 합산하는지 분리하는지
8. 최종 표의 소수점 자리수
9. 표의 행/열 및 셀 병합 규칙
10. 회사 표준 Layer / Text Style / Table Style

이 규칙을 먼저 정의하면 이후에는

```text
QTO 자동생성
→ Material 자동 Mapping
→ 측점별 수량 추출
→ 수량 분류
→ AutoCAD 2D 표 자동작성
```

까지 하나의 버튼으로 연결할 수 있다.

---

## 핵심 결론

**현재 개발 중인 Civil 3D 애드인의 방향은 충분히 구현 가능하다.**

특히 `Material / QTO API`는 애드인이 자동으로 생성하고 사용할 수 있으므로, 사용자가 Civil 3D에서 수동으로 재료정의를 만드는 작업을 없앨 수 있다.

다만 최종 목표가 기존 2D 설계도면의 표를 그대로 재현하는 것이라면,

> **QTO를 최종 도면 표현 도구로 사용하는 것이 아니라 수량 계산 엔진 중 하나로 사용하고, 최종 표는 애드인이 AutoCAD Table로 직접 생성하는 방식**

을 가장 추천한다.

또한 터파기 5m 기준, 지층별 구분, 용수, 면고르기, 비탈면 보호공 등은 QTO만으로 처리하기보다 자체 Geometry 계산엔진을 병행하는 것이 장기적으로 더 안정적이다.
