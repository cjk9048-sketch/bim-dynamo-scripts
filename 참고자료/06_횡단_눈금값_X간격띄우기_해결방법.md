# Civil 3D 2026 횡단면도 `CenterAxis.OffsetX` 문제 해결방안

## 1. 문제 요약

현재 DH.Grading Civil 3D 2026 .NET 애드인에서 횡단면도(`SectionView`)의 수직축 눈금값을 일정 거리 띄우기 위해 `AxisTickStyle.OffsetX`를 사용하고 있다.

동일한 코드로 다섯 축을 처리할 때 다음 현상이 발생한다.

| 축 | `Size` / `TextHeight` | `OffsetX` |
|---|---|---|
| `LeftAxis` | 정상 변경 | 정상 변경 |
| `CenterAxis` | 정상 변경 | 변경되지 않음 |

특히 `CenterAxis`의 `OffsetX`는 예외 없이 setter가 실행되고, 같은 트랜잭션 및 커밋 후 새 트랜잭션에서 값을 다시 읽으면 입력한 값이 남아 있다. 그러나 Civil 3D 스타일 대화상자를 다시 열면 기존 값이 표시된다.

따라서 단순한 C# setter 실패나 트랜잭션 문제가 아니라 **CenterAxis에서 `OffsetX`가 UI/표시 로직과 다르게 처리되는 문제**일 가능성이 높다.

---

## 2. 현재 코드

```csharp
using var tr = db.TransactionManager.StartTransaction();

if (tr.GetObject(styleId, OpenMode.ForWrite) is SectionViewStyle st)
{
    foreach (var get in new Func<AxisStyle>[]
             {
                 () => st.CenterAxis,
                 () => st.LeftAxis,
                 () => st.RightAxis,
                 () => st.TopAxis,
                 () => st.BottomAxis
             })
    {
        using var ax = get();
        if (ax == null) continue;

        ax.MajorTickStyle.TextHeight = 0.0045;
        ax.MajorTickStyle.Size = 0.0045;
        ax.MinorTickStyle.Size = 0.00225;
        ax.MajorTickStyle.Justification =
            AxisTickJustificationType.BottomOrRight;

        ax.MajorTickStyle.OffsetX = 0.018;
    }
}

tr.Commit();
```

`Size`와 `TextHeight`는 정상적으로 반영되지만 `CenterAxis.MajorTickStyle.OffsetX`만 UI에 반영되지 않는다.

---

# 3. 가장 먼저 할 테스트

`MajorTickStyle`을 중첩해서 직접 접근하지 말고 지역 변수에 받아서 테스트한다.

```csharp
var center = st.CenterAxis;

var major = center.MajorTickStyle;
var minor = center.MinorTickStyle;
var horizontal = center.HorizontalGeometryTickStyle;

ed.WriteMessage(
    $"\n===== CENTER AXIS =====" +
    $"\nMajor OffsetX={major.OffsetX}, OffsetY={major.OffsetY}" +
    $"\nMinor OffsetX={minor.OffsetX}, OffsetY={minor.OffsetY}" +
    $"\nHorizontal OffsetX={horizontal.OffsetX}, OffsetY={horizontal.OffsetY}"
);

major.OffsetX = 0.018;

ed.WriteMessage(
    $"\nAFTER Major.OffsetX={major.OffsetX}");
```

이 테스트의 목적은 다음 두 가지를 확인하는 것이다.

1. 중첩 속성 접근 때문에 값이 제대로 저장되지 않는지
2. `CenterAxis`에서 실제 UI와 연결된 `AxisTickStyle`이 무엇인지

현재까지의 증거상 1번 가능성은 낮다. `Size`와 `TextHeight`가 같은 방식으로 정상 작동하기 때문이다.

---

# 4. UI와 API 값 비교

Civil 3D에서 다음 위치로 들어간다.

> 횡단면도 뷰 스타일 → 수직축 → 중심 → 주 눈금 상세정보 → X 간격 띄우기

UI에서 값을 예를 들어 다음과 같이 변경한다.

```text
7 → 12 → 18
```

각 단계에서 API로 다음 값을 읽는다.

```csharp
CenterAxis.MajorTickStyle.OffsetX
CenterAxis.MajorTickStyle.OffsetY
CenterAxis.MajorTickStyle.Size
CenterAxis.MajorTickStyle.TextHeight

CenterAxis.HorizontalGeometryTickStyle.OffsetX
CenterAxis.HorizontalGeometryTickStyle.OffsetY
```

### 판별 방법

#### 경우 A

UI에서 X 간격 띄우기를 변경하면:

```text
MajorTickStyle.OffsetX
```

가 같이 변한다.

그런데 코드에서:

```csharp
center.MajorTickStyle.OffsetX = 0.018;
```

를 실행해도 UI가 변하지 않는다면,

**Civil 3D 2026의 CenterAxis에 대한 API setter와 UI/렌더링 사이의 불일치**를 의심한다.

#### 경우 B

UI 변경 시:

```text
HorizontalGeometryTickStyle.OffsetX
```

가 변한다면,

현재 코드가 잘못된 `AxisTickStyle`을 수정하고 있는 것이다.

#### 경우 C

위 값들이 모두 변하지 않는다면,

UI의 "X 간격 띄우기"가 공개 API의 `AxisTickStyle.OffsetX`와 다른 내부 데이터로 관리될 가능성이 있다.

---

# 5. `Justification`은 분리해서 테스트

현재 코드는 `Justification`과 `OffsetX`를 동시에 변경한다.

```csharp
ax.MajorTickStyle.Justification =
    AxisTickJustificationType.BottomOrRight;

ax.MajorTickStyle.OffsetX = 0.018;
```

따라서 먼저 다음처럼 `Justification`을 완전히 제거하고 테스트한다.

```csharp
var mt = st.CenterAxis.MajorTickStyle;

mt.OffsetX = 0.018;
```

정상 작동 여부를 확인한 다음:

```csharp
mt.Justification =
    AxisTickJustificationType.BottomOrRight;
```

를 추가한다.

### 판단

```text
OffsetX만 설정
→ 정상

OffsetX + Justification
→ 비정상
```

이라면 `Justification`과의 상호작용을 조사한다.

다만 현재까지 확인된 현상만 보면 `Justification`이 근본 원인일 가능성은 높지 않다.

---

# 6. `OffsetY`로 바꾸는 것은 권장하지 않음

`AxisTickStyle`에는 다음 두 속성이 있다.

```text
OffsetX
OffsetY
```

중심축이 세로축이라는 이유로 `OffsetY`를 사용하는 것은 적절하지 않을 가능성이 높다.

현재 Civil 3D UI가 명확하게:

> X 간격 띄우기

라고 표시하고 있고, 사람이 UI에서 이 값을 변경하면 정상적으로 동작한다.

따라서 기본 방향은:

```csharp
MajorTickStyle.OffsetX
```

를 유지한다.

`OffsetY`는 진단 과정에서 비교값으로만 확인한다.

---

# 7. 단위 문제 가능성도 낮음

현재 사용하는 값:

```csharp
OffsetX = 0.018;
```

은 18 mm를 의미하도록 사용하고 있다.

프로젝트에서는 `Size`, `TextHeight`도 같은 방식으로 스타일값을 계산하며 정상 작동한다.

따라서:

```text
0.018이 잘못된 단위라서 OffsetX가 무시된다
```

라고 보기는 어렵다.

단위 문제라면 `LeftAxis`에서도 동일한 문제가 발생해야 한다.

---

# 8. `HorizontalGeometryTickStyle` 확인

`AxisStyle`에는 다음과 같은 서로 다른 스타일 객체가 있다.

```csharp
AxisTickStyle HorizontalGeometryTickStyle
AxisTickStyle MinorTickStyle
AxisTickStyle MajorTickStyle
```

따라서 CenterAxis에서 실제 표시되는 눈금/라벨이 어느 객체의 속성을 참조하는지 확인해야 한다.

진단용으로 다음과 같이 모두 같은 값을 넣어볼 수 있다.

```csharp
var center = st.CenterAxis;

var major = center.MajorTickStyle;
var minor = center.MinorTickStyle;
var horizontal = center.HorizontalGeometryTickStyle;

major.OffsetX = 0.018;
minor.OffsetX = 0.018;
horizontal.OffsetX = 0.018;
```

주의:

위 코드는 **최종 해결 코드가 아니라 진단용 코드**이다.

어떤 값을 변경했을 때 UI의 "X 간격 띄우기"가 영향을 받는지 확인하는 것이 목적이다.

---

# 9. 가장 중요한 진단 결과

현재까지의 테스트 결과가 다음과 같다고 가정한다.

```text
코드 입력
CenterAxis.MajorTickStyle.OffsetX = 0.018

↓

같은 트랜잭션에서 읽기
0.018

↓

Commit

↓

새 트랜잭션에서 읽기
0.018

↓

Civil 3D 스타일 대화상자
기존 값 0.012
```

이 경우 다음은 원인에서 제외할 수 있다.

- C# setter 자체가 실패
- Transaction Commit 실패
- 객체가 ReadOnly
- 값의 단위가 완전히 잘못됨
- `MajorTickStyle` 접근 자체가 실패

반대로 다음 가능성이 커진다.

> **Civil 3D 2026의 CenterAxis에 대한 `OffsetX` 저장값과 UI/렌더링에서 사용하는 값이 서로 다르거나, CenterAxis가 별도의 내부 처리 경로를 사용하는 문제**

---

# 10. 최종 애드인 구조

현재 애드인의 축척 처리 구조는 유지하는 것이 좋다.

```text
원하는 종이상 크기
        ↓
PaperToStyle()
        ↓
축척 보정 스타일값
        ↓
SectionViewStyle
        ↓
AxisTickStyle
        ↓
OffsetX
```

프로젝트는 한 도면에서 종단도와 횡단도를 서로 다른 축척으로 사용하는 상황이므로 Annotation Scale을 변경하지 않고 스타일값을 축척별로 역산하는 방식이 필요하다.

예:

```csharp
스타일값 =
    원하는종이크기 × 실제축척 ÷ 주석축척;
```

따라서 단순히 DWT 템플릿에 고정값을 넣는 방식으로 되돌아가는 것은 권장하지 않는다.

# 11. 권장 해결 순서

## 1단계 — 지역 변수 사용

```csharp
var center = st.CenterAxis;
var mt = center.MajorTickStyle;

mt.OffsetX = 0.018;
```

## 2단계 — Justification 제거

```csharp
// mt.Justification = ...;
mt.OffsetX = 0.018;
```

## 3단계 — UI와 API 값 비교

UI에서:

```text
X 간격 띄우기 7 → 12 → 18
```

API에서:

```text
MajorTickStyle.OffsetX
MinorTickStyle.OffsetX
HorizontalGeometryTickStyle.OffsetX
```

를 비교한다.

## 4단계 — CenterAxis와 LeftAxis 비교

동일한 코드를 실행하고 결과를 비교한다.

```text
LeftAxis.OffsetX
CenterAxis.OffsetX
```

## 5단계 — 실제 UI 연결 객체 확인

UI에서 변경했을 때 어느 API 속성이 같이 변하는지 찾는다.

## 6단계 — 그래도 불일치하면 Civil 3D API 문제로 판단

다음 조건을 모두 만족하면 API/UI 불일치 가능성이 매우 높다.

```text
CenterAxis.MajorTickStyle.OffsetX
        ↓
setter 정상
        ↓
DB 재조회 정상
        ↓
LeftAxis에서는 정상
        ↓
CenterAxis UI는 변경 안 됨
```

이 경우 `OffsetY`나 템플릿으로 우회하기보다 **CenterAxis에 대한 별도 처리 방법 또는 Autodesk API의 다른 접근법을 찾는 것이 맞다.**

# 12. 핵심 결론

현재 증상만 놓고 보면 다음과 같이 판단하는 것이 가장 합리적이다.

### 가능성이 낮은 원인

- `OffsetX` 단위 문제
- `OffsetY`를 써야 하는 문제
- Transaction 문제
- `MajorTickStyle` 중첩 접근 문제
- 단순 setter 오류

### 확인이 필요한 원인

- `Justification`과의 상호작용
- `HorizontalGeometryTickStyle`과의 관계
- CenterAxis의 UI/API 내부 매핑 차이

### 가장 유력한 원인

**Civil 3D 2026에서 CenterAxis의 `OffsetX`가 공개 API상으로는 정상적인 get/set 속성이지만, SectionViewStyle UI 또는 실제 표시 로직에서는 다른 내부 값을 사용하거나 해당 setter를 정상적으로 반영하지 않는 문제**

따라서 다음 테스트에서 **UI의 "X 간격 띄우기"를 변경했을 때 어떤 `AxisTickStyle`의 값이 실제로 바뀌는지 확인하는 것**이 가장 중요하다.

그 결과에 따라 최종 코드 수정 방향을 결정한다.
