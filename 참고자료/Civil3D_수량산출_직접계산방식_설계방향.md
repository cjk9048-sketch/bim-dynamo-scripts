# Civil 3D 수량산출 직접계산 방식 설계 방향

## 1. 결론

현재 개발 중인 Civil 3D 애드인의 방향이라면 QTO(Material/Quantity Takeoff)에 의존하기보다 **자체 Geometry 기반 직접계산 방식으로 가는 것이 장기적으로 유리하다.**

특히 향후 **지하지층 모델링까지 확장할 계획**이라면 직접계산 방식이 더 적합하다.

QTO가 나쁜 것이 아니라, 현재 애드인의 최종 목표가 단순한 토공 수량산출이 아니라 다음까지 확장되기 때문이다.

- 원지반 생성
- 계획지반 생성
- 터파기 모델 생성
- 횡단도 자동화
- 기존 2D 설계도면 형식의 수량표 자동작성
- 향후 지하지층 모델링
- 토질/암종별 수량산출

---

## 2. QTO보다 직접계산이 유리한 이유

단순한 구조라면 QTO를 활용할 수 있다.

```text
원지반
  ↓
계획지반
  ↓
절토/성토
  ↓
QTO
  ↓
수량
```

하지만 향후 지하지층까지 들어가면 계산 구조가 복잡해진다.

예를 들어:

```text
지표면
────────────────────

표토
~~~~~~~~~~~~~~~~~~~~

매립층
--------------------

퇴적층
====================

풍화토
....................

풍화암
////////////////////

연암
####################
```

이 상태에서 터파기 영역과 각각의 지층을 교차시켜야 한다.

```text
터파기 영역
      ∩
토사 영역
      ↓
토사 터파기

터파기 영역
      ∩
풍화암 영역
      ↓
풍화암 터파기

터파기 영역
      ∩
연암 영역
      ↓
연암 터파기
```

이러한 구조는 Civil 3D QTO의 기본 Material 체계보다 **자체 Geometry Engine으로 구현하는 것이 더 자연스럽다.**

---

## 3. 직접계산 방식의 핵심 개념

직접계산이라고 해서 Civil 3D의 기능을 모두 버리는 것은 아니다.

다음과 같이 역할을 분리하는 것이 좋다.

```text
Civil 3D
    ↓
Geometry/API 데이터 추출
    ↓
자체 계산 엔진
    ↓
수량 데이터
    ↓
도면 생성 엔진
```

즉,

> **Civil 3D는 Geometry와 도면 플랫폼으로 사용하고, 수량산출 규칙은 애드인이 소유한다.**

이 구조가 핵심이다.

---

## 4. 추천하는 전체 구조

```text
                 [Civil 3D]
                     │
             Geometry 추출
                     ↓
            ┌────────────────┐
            │ Geometry Engine│
            └───────┬────────┘
                    ↓
             [영역/경계 계산]
                    ↓
             [Quantity Engine]
                    ↓
          ┌─────────┼─────────┐
          ↓         ↓         ↓
       횡단도     수량표     집계표
          ↓         ↓         ↓
       DWG 도면    DWG       Excel
```

---

## 5. 횡단면 기반 Geometry Engine

현재 애드인이 이미 원지반, 터파기, 계획지반 및 횡단도 생성까지 수행한다면 다음 단계는 **횡단면 Geometry를 공통 데이터로 변환하는 기능**을 만드는 것이다.

```text
Civil 3D Surface
       ↓
Sample Line
       ↓
Section 데이터
       ↓
Point List
       ↓
Line / Polyline
       ↓
Polygon
       ↓
면적 / 교차 / 차집합
```

이 Geometry Engine을 공통으로 사용하면 여러 공종을 같은 방식으로 계산할 수 있다.

---

## 6. 터파기 계산

터파기는 기본적으로 원지반과 터파기선을 이용해 폐합 영역을 만든 뒤 면적을 계산한다.

```text
원지반선
──────────────╲
               ╲
                ╲
                 │
                 │
                 └────────
                 터파기선
```

각 측점에서 횡단면적을 계산하고, 측점 간 거리를 이용해 체적을 계산할 수 있다.

---

## 7. 5m 이하 / 5m 이상 터파기

현재 도면의 중요한 규칙 중 하나가 다음과 같은 구분이다.

```text
터파기 (5.0m 이하)
터파기 (5.0m 이상)
```

단순히 Material을 두 개 만드는 것보다 자체 계산하는 것이 유리하다.

```text
터파기 영역
      ↓
각 지점의 깊이 계산
      ↓
5.0m 기준선 생성
      ↓
┌─────────────────┐
│ 5m 이하 영역    │
├─────────────────┤
│ 5m 이상 영역    │
└─────────────────┘
      ↓
토사 / 풍화암 / 연암과 교차
      ↓
각 공종별 수량 계산
```

---

## 8. 지층 모델링과의 연계

향후 지하지층 모델링을 추가하면 직접계산 방식의 장점이 더욱 커진다.

예를 들어 각 지층을 횡단면상 경계선으로 표현한다.

```text
원지반
────────────────────────

토사
~~~~~~~~~~~~~~~~~~~~~~~~

풍화암
------------------------

연암
////////////////////////
```

그리고 터파기 영역과 지층 영역의 교집합을 계산한다.

```text
터파기 Polygon
      │
      ├── ∩ 토사 Polygon
      │       ↓
      │   토사 굴착량
      │
      ├── ∩ 풍화암 Polygon
      │       ↓
      │   풍화암 굴착량
      │
      └── ∩ 연암 Polygon
              ↓
          연암 굴착량
```

지층이 추가되어도 계산엔진 자체를 크게 변경하지 않고 확장할 수 있다.

---

## 9. 공종별 계산 구조

### 9.1 터파기

```text
터파기 영역
→ 면적
→ 측점 간 체적
→ 누계
```

### 9.2 되메우기

```text
터파기 영역
      -
구조물/관로 영역
      ↓
되메우기 영역
```

### 9.3 성토

```text
계획지반
──────────────

성토 영역

──────────────
원지반
```

### 9.4 바닥면 고르기

터파기 바닥의 수평 또는 설계 경사 구간 길이 등을 이용해 면적을 계산한다.

### 9.5 면고르기

성토면과 절토면을 구분하여 실제 비탈면 또는 대상 면적을 계산한다.

### 9.6 비탈면 보호공

횡단면에서 비탈면의 실제 경사 길이를 계산하여 대상 구간의 면적을 산출한다.

### 9.7 표토제거

```text
표토 제거 깊이 × 대상 폭
```

또는 실제 표토 Surface와 계획면의 교차영역을 이용한다.

### 9.8 벌개제근

대상 면적을 산출하는 방식으로 처리할 수 있다.

---

## 10. 수량 데이터 모델을 별도로 만드는 것이 중요

계산 결과를 바로 AutoCAD Table에 넣지 않는 것이 좋다.

애드인 내부에 공통 수량 데이터 모델을 만든다.

```csharp
class QuantityItem
{
    string Code;
    string Name;
    string Category;
    string Material;
    string Unit;
    double Quantity;
    string CalculationMethod;
}
```

측점별 데이터까지 관리한다면 다음과 같이 확장할 수 있다.

```csharp
class StationQuantity
{
    double Station;
    string Code;
    string Name;
    string Material;
    double Area;
    double Volume;
    double Length;
    string Unit;
}
```

계산엔진과 도면엔진을 완전히 분리할 수 있다.

---

## 11. 최종 도면 생성

```text
Geometry Engine
      ↓
Quantity Engine
      ↓
StationQuantity
      ↓
Table Renderer
      ↓
AutoCAD Table
```

AutoCAD Table에서는 다음을 직접 제어할 수 있다.

- 행/열 수
- 셀 병합
- 행 높이
- 열 너비
- 문자 높이
- 문자 정렬
- 선 색상
- 선 두께
- Layer
- Table Style
- Text Style
- 공종 표시 순서
- 소수점 자리수

따라서 기존 2D 설계도면과 유사한 표를 자동 생성할 수 있다.

---

## 12. 직접계산 방식의 가장 큰 장점

QTO를 사용하면 계산 구조가 Civil 3D의 QTO 개념에 어느 정도 종속된다.

직접계산 방식에서는 애드인이 원하는 규칙을 그대로 구현할 수 있다.

예:

```text
5m 기준
+
지층 경계
+
용수 조건
+
좌/우 구분
+
구조물 형상
+
관로 형상
+
회사 수량산출 기준
```

을 하나의 계산 규칙으로 통합할 수 있다.

---

## 13. 향후 확장 가능성

자체 Geometry/Quantity Engine을 만들면 다음 기능까지 확장하기 쉽다.

```text
원지반
   ↓
계획지반
   ↓
터파기
   ↓
지하지층 모델
   ↓
토질별 굴착량
   ↓
암종별 굴착량
   ↓
되메우기
   ↓
성토
   ↓
토공 수량 집계
   ↓
횡단도
   ↓
수량표
   ↓
Excel / 물량집계
```

단순한 횡단도 자동작성 애드인이 아니라 **토공 수량산출 및 도면 자동화 엔진**으로 발전시킬 수 있다.

## 14. 추천 개발 우선순위

### STEP 1. 횡단 Geometry 추출

```text
Surface
Sample Line
Section
Polyline
Point
```

등을 공통 데이터로 변환한다.

### STEP 2. Geometry 연산 기능

먼저 다음 기능을 만든다.

```text
교차점 계산
Line 교차
Polyline 교차
Polygon 생성
Polygon Intersection
Polygon Difference
Polygon Union
면적 계산
길이 계산
```

### STEP 3. 기본 수량 계산

```text
터파기
성토
되메우기
```

부터 구현한다.

### STEP 4. 세부 공종

```text
바닥면 고르기
면고르기
비탈면 보호공
표토제거
벌개제근
```

을 추가한다.

### STEP 5. 지하지층 모델

```text
지층 경계
지층 Polygon
지층별 Intersection
```

을 추가한다.

### STEP 6. 수량표

마지막으로 계산 결과를 기존 2D 설계도면 양식으로 출력한다.

## 15. 가장 중요한 설계 원칙

계산엔진을 특정 공종에 종속시키지 않는 것이 중요하다.

### 권장 구조

```text
             Geometry Engine
                    ↓
             Area/Intersection
                    ↓
             Quantity Engine
                    ↓
          ┌─────────┼─────────┐
          ↓         ↓         ↓
        터파기     성토      지층별
          ↓         ↓       굴착량
          └─────────┼─────────┘
                    ↓
              Quantity Data
                    ↓
             Drawing Engine
```

### 피해야 할 구조

```text
터파기 코드
 ├─ Civil3D API
 ├─ 면적 계산
 ├─ 지층 계산
 ├─ 수량표 작성
 └─ AutoCAD Table 생성
```

공종별 코드 안에 모든 기능을 넣으면 나중에 지층 모델링을 추가할 때 수정 범위가 매우 커진다.

---

## 16. 최종 판단

현재 결정한 **직접계산 방식은 적절하다.**

특히 다음 조건에서는 직접계산이 더 유리하다.

- 향후 지하지층 모델링 예정
- 토질/암종별 수량 필요
- 5m 이하/이상과 같은 회사 또는 설계기준 적용
- 용수 여부 등 추가 조건 필요
- 기존 2D 도면 양식으로 출력 필요
- 공종별 계산 규칙이 계속 추가될 가능성
- Excel 및 최종 수량집계까지 연결할 계획

따라서 개발 방향은 다음과 같이 잡는 것을 권장한다.

> **Civil 3D = 데이터 및 Geometry 플랫폼**
>
> **자체 Geometry Engine = 영역/경계 계산**
>
> **자체 Quantity Engine = 수량산출 규칙**
>
> **Drawing Engine = 횡단도 및 수량표 자동작성**

이렇게 하면 향후 지하지층 모델링까지 확장해도 기존 구조를 유지하면서 기능을 추가할 수 있다.

                            │

                  ┌──────────────────┐

                  │ Difference       │

                  │ Length           │

                           ↓
                  ┌──────────────────┐
                  │ Quantity Engine  │
                  │                  │
                  │ 터파기            │
                  │ 성토              │
                  │ 되메우기          │
                  │ 면고르기          │
                  │ 비탈면            │
                  │ 표토제거          │
                  │ 지층별 굴착       │

                  ┌──────────────────┐
                  │ Quantity Data    │

                           ↓
              ┌────────────┴────────────┐
              ↓                         ↓
      ┌────────────────┐        ┌────────────────┐
