# [자문 답변 #7] 이중 경계선(Double Line) 및 오목부(Concave) 계단 완벽 해결 가이드

> **문서 요약:** Outer Boundary 트림 시 표면 모서리가 화면 선과 어긋나는 현상(이중선)을 해결하기 위해 **Daylight 정점화(AddVertices)**를 적용하고, 오목부에서 용접(Weld)이 빗나가는 한계를 극복하기 위해 강제 스냅을 폐기하고 **End-Cap(단끝 닫음선) 브레이크라인** 위상을 새로 추가합니다.

---

## 1. 문제 ①: 초록선 2개 겹침 (이중선) 해결

### [진단] 왜 두 줄이 되는가?
Outer Boundary는 파괴식으로 '자르는 가위' 역할만 합니다. 자르려는 경계선 상에 삼각망 노드(점)가 존재하지 않으면, TIN 엔진은 근처에 있는 점들끼리 대충 이어진 삼각형의 모서리를 파괴합니다. 그 결과 실제 표면의 끝선은 지그재그가 되며 부드러운 초록색 Daylight 선과 어긋나 두 줄로 보이게 됩니다.

### [해결책] Daylight 정점화 (AddVertices) + Safe-Zone 채움
가위를 대는 선에 노드를 직접 만들어 주면 됩니다. 브레이크라인(교차 오류 위험)으로 넣지 말고, 순수하게 **`AddVertices`**에 Daylight 좌표를 쏟아 붓습니다.

**핵심 주의사항:** 채움 정점(Fill Vertices)이 Daylight 선 근처(예: 0.5m 이내)에 촘촘하게 존재하면 삼각망이 얽혀 또 톱니가 생길 수 있습니다. 
따라서 **채움 정점은 Daylight 선으로부터 0.5m 이상 떨어진 것들만 필터링해서 넣고, 빈 공간은 Daylight 정점이 담당하게 구성**합니다.

```csharp
// [TIN 조립 부분 수정] SurfaceBuilder.cs

// 1. 단 모서리 브레이크라인 (그대로 유지)
foreach (var ring in benchRings) AddBreakline(tin, ring);

// 2. [추가] 채움 정점 필터링 (Daylight와 너무 가까운 점 솎아내기)
var safeFillVertices = new Point3dCollection();
foreach(var pt in fillVertices)
{
    // Daylight 폴리곤 선과의 최단 거리 계산
    double distToBoundary = DistToDaylightLine(pt, daylightPoly);
    if (distToBoundary > 0.5) // 0.5m Safe-Zone
    {
        safeFillVertices.Add(pt);
    }
}
tin.AddVertices(safeFillVertices);

// 3. [핵심] Daylight 선의 모든 포인트를 정점으로 추가!
// 교차 오류를 일으키는 Breakline 속성 없이 순수 노드만 제공하여 1줄 트림 유도
tin.AddVertices(daylightPoints); 

tin.Rebuild();

// 4. Outer 경계 (파괴식 트림)
tin.BoundariesDefinition.AddBoundaries(daylightPc, 1.0, SurfaceBoundaryType.Outer, false);
tin.Rebuild();
```
* **결과:** 표면 모서리가 촘촘히 박힌 Daylight 정점을 따라 칼같이 한 줄로 잘립니다. 톱니도 없고, 이중선도 사라집니다.

## 2. 문제 ②: 사면 오목부(Concave) 단끝 계단 잔존

### [진단] 오목부에서 위상 용접(Weld)이 실패하는 이유
오목 코너(L자 꺾임 안쪽)에서는 NTS `Buffer` 오프셋 링이 바깥으로 퍼지는 게 아니라 안으로 모이면서(수축하면서) 길이가 짧아지거나 소실됩니다. 
즉, Top Arc(사면 위)보다 Toe Arc(소단 바깥)의 길이가 훨씬 짧고 모양이 찌그러지며, 때로는 아예 다른 개수의 조각으로 찢어집니다. 
이 상황에서 6m 반경 내의 끝점을 찾아 강제로 스냅(XY 덮어쓰기)을 하려니, 매칭이 어긋나거나 너무 멀어 용접이 안 되어 삼각 탭이 그대로 남아버린 것입니다.

### [해결책] 강제 스냅 폐기 & End-Cap(단끝 닫음선) 브레이크라인 추가
억지로 XY 좌표를 하나로 합치려 하지 마세요. 두 선이 떨어진 채 Pinch-out 되었다면, **그 떨어진 두 끝점을 이어버리는 짧은 브레이크라인 선분(End-Cap)**을 추가하여 옆구리를 막아버리면 됩니다.

* Top 끝점과 Toe 끝점은 둘 다 Z=110m (단 고도)로 동일합니다.
* 이 두 점을 잇는 브레이크라인을 넣으면, 삼각망이 수직 빗살을 만들지 않고 **평평한 뚜껑(수평면)**으로 옆구리를 단정하게 닫아 지형에 흡수시킵니다.

```csharp
// [기존 강제 스냅(WeldBenchEnds) 코드를 삭제하고 아래 로직으로 교체]

// Top Arc 끝점들과 Toe Arc 끝점들을 수집하여 서로 이어주는 End-Cap 생성
private static void CreateEndCaps(List<List<Point3>> topArcs, List<List<Point3>> toeArcs, CivilDB.TinSurface tin)
{
    // 매칭 톨러런스를 넉넉하게 10m 정도로 잡습니다. 
    // 오목부에선 링이 심하게 수축해 거리가 멀 수 있기 때문입니다.
    double capTolerance = 10.0; 

    foreach (var toe in toeArcs)
    {
        if (toe.Count < 1) continue;

        Point3 toeStart = toe[0];
        Point3 toeEnd = toe[^1];

        // 1. Toe 시작점에 대한 End-Cap
        Point3? topForStart = FindClosestEnd(toeStart, topArcs, capTolerance);
        if (topForStart.HasValue)
        {
            // XY 덮어쓰기가 아님! 두 점을 잇는 점 2개짜리 브레이크라인 추가
            var capPts = new Point3dCollection { toeStart, topForStart.Value };
            
            // 길이가 0.1m 이상 유의미할 때만 브레이크라인 추가
            if (Dist2D(toeStart, topForStart.Value) > 0.1)
                tin.BreaklinesDefinition.AddStandardBreakline(capPts, 1.0, 1.0, 0.05, 0.0);
        }

        // 2. Toe 끝점에 대한 End-Cap
        Point3? topForEnd = FindClosestEnd(toeEnd, topArcs, capTolerance);
        if (topForEnd.HasValue)
        {
            var capPts = new Point3dCollection { toeEnd, topForEnd.Value };
            
            if (Dist2D(toeEnd, topForEnd.Value) > 0.1)
                tin.BreaklinesDefinition.AddStandardBreakline(capPts, 1.0, 1.0, 0.05, 0.0);
        }
    }
}
```

### 3. 결론
1. **Daylight 정점 추가 (`AddVertices`) + Safe-Zone 채움 필터링**을 통해 가위로 자를 때 생기는 이중선과 톱니를 모두 잡을 수 있습니다. 화면에 그리는 폴리선과 표면 모서리가 100% 일치하게 됩니다.
2. 억지스러운 XY 용접(스냅)을 폐기하고, 벌어진 틈을 평평한 수평선으로 연결하는 **End-Cap 브레이크라인** 기법을 적용하면, 기하학적 형태가 꼬이는 오목부 코너에서도 빗살이나 계단이 생기지 않고 지형과 자연스럽게 맞물려 소멸합니다.
