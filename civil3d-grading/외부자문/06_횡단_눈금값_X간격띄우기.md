# 자문 요청 — Civil 3D 횡단면도 뷰 스타일: `AxisTickStyle.OffsetX`만 안 먹는다

작성: 2026-08-27 · DH.Grading (Civil 3D 2026 .NET 애드인, C#)

---

## 1. 한 줄 요약

**같은 코드로 다섯 축을 훑는데, `LeftAxis`의 `OffsetX`는 바뀌고 `CenterAxis`의 `OffsetX`만 안 바뀝니다.**

그리고 `CenterAxis`에서도 **`Size`·`TextHeight`는 잘 바뀝니다.** 즉 `CenterAxis` 객체 자체는 살아 있는데 **그 안의 `OffsetX`만** 안 먹습니다.

예외는 안 납니다. 되읽으면 우리가 쓴 값이 돌아오는데, **스타일 대화상자는 옛 값 그대로**입니다.

---

## 2. 무엇을 하려는가

횡단면도(`SectionView`)의 **표고축 눈금값**을 축에서 일정 거리 띄우려 합니다.

Civil 3D UI에서는 이 자리입니다:

```
횡단면도 뷰 스타일 → [수직축] 탭 → 조정할 축: [중심]
  → 주 눈금 상세정보 → X 간격 띄우기 = 12
```

**사람이 이 대화상자에서 바꾸면 잘 됩니다.** 코드로만 안 됩니다.

---

## 3. 코드

```csharp
using var tr = db.TransactionManager.StartTransaction();
if (tr.GetObject(styleId, OpenMode.ForWrite) is SectionViewStyle st)
{
    foreach (var get in new Func<AxisStyle>[]
             { () => st.CenterAxis, () => st.LeftAxis, () => st.RightAxis,
               () => st.TopAxis,    () => st.BottomAxis })
    {
        using var ax = get();
        if (ax == null) continue;

        ax.MajorTickStyle.TextHeight   = 0.0045;   // ✅ 반영됨 (4.5mm)
        ax.MajorTickStyle.Size         = 0.0045;   // ✅ 반영됨
        ax.MinorTickStyle.Size         = 0.00225;  // ✅ 반영됨
        ax.MajorTickStyle.Justification = AxisTickJustificationType.BottomOrRight;
        ax.MajorTickStyle.OffsetX      = 0.018;    // ❌ 안 됨 (18mm를 넣어도 12 그대로)
    }
}
tr.Commit();
```

`styleId`는 **뷰가 실제로 쓰는 스타일**입니다(`sectionView.StyleId`로 얻음). 다섯 축을 모두 훑으므로 어느 축이 켜져 있든 걸립니다.

---

## 4. 실측한 것

### 4.1 되읽으면 우리가 쓴 값이 나온다

같은 트랜잭션에서 되읽어도, **커밋 후 새 트랜잭션에서 되읽어도** 우리가 쓴 값입니다:

```
[커밋 뒤 확인: 중심 12.0mm — 남았다]
```

그런데 **스타일 대화상자를 새로 열면 7mm**였습니다(당시 값).

### 4.2 예외는 없다

`try/catch`로 감쌌고 예외가 잡힌 적이 없습니다. 다른 속성(`Size` 등)은 **같은 블록에서 성공**합니다.

### 4.3 같은 객체의 다른 속성은 된다

사용자(JACK) 확인:
> "주눈금 크기와 문자높이는 바뀌는데 **X 간격 띄우기는 계속 12인 상태**야."

`Size`와 `TextHeight`는 화면에서 실제로 변합니다. `OffsetX`만 안 변합니다.

### 4.4 ★★ 축마다 다르다 — 왼쪽은 되고 중심만 안 된다 ← 가장 중요한 단서

사용자(JACK) 확인:
> "희한한 건 스타일 대화상자에서 **왼쪽을 선택한 상태의 X 간격 띄우기는 계속 바뀌는데**,
> 우리한테 필요한 **중심을 선택했을 때 나오는 X 간격 띄우기는 계속 12**야."

**같은 반복문·같은 속성·같은 값인데 축에 따라 갈립니다.**

| 축 | `Size` · `TextHeight` | `OffsetX` |
|---|---|---|
| `LeftAxis` | 바뀜 | **바뀜** |
| `CenterAxis` | 바뀜 | **안 바뀜** |

그래서 이 문제는 `OffsetX` 속성의 문제가 아니라 **`CenterAxis`가 다른 물건**이라는 쪽으로 보입니다.

### 4.5 ★★★ `OffsetY`도 마찬가지다 — 중심축은 오프셋을 아예 안 받는다

`OffsetX`와 `OffsetY`를 **둘 다** 쓰고, 도면 배치를 바꿔 축척을 여러 번 바꿔 가며 실측했습니다.

| 축 | `Size` | `TextHeight` | `OffsetX` | `OffsetY` |
|---|---|---|---|---|
| `LeftAxis` | ✅ | ✅ | **✅ 축척 따라 바뀜** | **✅ 축척 따라 바뀜** |
| `CenterAxis` | ✅ | ✅ | **❌ 변화 없음** | **❌ 변화 없음** |

사용자(JACK) 확인:
> "도면 배열을 바꿔서 축척을 바꾸면 **왼쪽의 X·Y 간격 띄우기는 값이 바뀌어**.
> 그런데 **중심의 X·Y는 변화가 없어, 둘 다**."

**같은 객체의 어떤 속성은 받고 어떤 속성은 안 받습니다.** 그래서 `CenterAxis`가 오프셋에 관해서만
**파생값이거나 실질적으로 읽기 전용**인 것으로 보입니다. (그런데 UI에서 사람이 바꾸면 반영됩니다.)

### 4.6 사람이 대화상자에서 바꾸면 된다

같은 스타일, 같은 축, 같은 항목을 **UI에서** 바꾸면 즉시 반영됩니다.

## 6. 우리가 의심하는 것

### ⓪ `CenterAxis`가 특별한가 ← 가장 유력하다고 봄

`LeftAxis`는 되고 `CenterAxis`만 안 된다면, 중심축이 **다른 저장소를 쓰거나 파생값**일 수 있다고 봅니다.

- `CenterAxis`는 좌우 축에서 **파생되는 값**입니까? 그래서 일부 속성만 자기 것을 갖습니까?
- 중심축의 눈금값 간격은 **다른 속성**(예: 그래프 폭이나 `TickAndLabelStartElevation`)에서 계산됩니까?
- `CenterAxis`에 쓰려면 **먼저 켜야 하는 스위치**(`ShowTickAndLabel` 등)가 있습니까?

### ① `Justification`과의 상호작용

우리는 **같은 블록에서 `Justification`을 함께 설정**합니다:

```csharp
ax.MajorTickStyle.Justification = AxisTickJustificationType.BottomOrRight;
ax.MajorTickStyle.OffsetX = 0.018;
```

**정렬 방식이 오프셋을 무효로 만들 수 있습니까?** 예를 들어 "축에 붙여 정렬"이면 오프셋이 무시되는 식으로요. 순서를 바꾸거나 `Justification`을 안 건드리면 달라집니까?

`AxisTickJustificationType`의 값이 무엇이고 각각 오프셋을 어떻게 다루는지 알고 싶습니다.

### ② 중첩 속성 접근이 임시 객체를 만드는가

`ax.MajorTickStyle.OffsetX = …`처럼 **속성을 두 번 타고 들어가** 값을 씁니다.
`MajorTickStyle`이 매번 새 래퍼를 반환한다면 값이 안 붙을 수 있는데, **그렇다면 `Size`도 안 되어야** 합니다. 그런데 `Size`는 됩니다. 그래서 이 가설은 약하다고 봅니다.

다만 확인하고 싶습니다 — **속성을 지역 변수에 받아 쓰면** 달라집니까?

```csharp
var mt = ax.MajorTickStyle;
mt.OffsetX = 0.018;
// 또는 using (var mt = ax.MajorTickStyle) { … }
```

### ③ 단위

Civil 스타일 값은 **종이 미터**로 알고 있습니다(밴드 높이 130mm = `0.130`). `Size`·`TextHeight`가 그 규칙으로 잘 동작하므로 `OffsetX`도 같으리라 봤습니다. 맞습니까?

### ④ ~~`OffsetY`를 써야 하는 것 아닌가~~ (실측으로 기각)

`AxisTickStyle`에는 `OffsetX`와 **`OffsetY`가 둘 다** 있습니다.

중심축은 **세로로 서 있는 축**이므로, 눈금값을 축에서 떼는 방향이 `X`가 아니라 `Y`일 수도 있다고 생각합니다.
다만 UI 항목 이름이 "**X** 간격 띄우기"이고 사람이 그것을 바꾸면 되므로, 그렇다면 UI와 API의 이름이 어긋나는 셈입니다.

**실측 결과 `OffsetY`도 안 됩니다**(4.5 참조). 그래서 방향의 문제가 아니라
**중심축이 오프셋 자체를 안 받는** 것으로 좁혀졌습니다.

- 중심축에서 눈금값 간격을 코드로 정하는 **다른 경로**가 있습니까?
- UI가 그 값을 어디에 저장합니까? .NET API로 그 자리에 닿을 수 있습니까?

### ⑤ 별도의 "덮어쓰기 스위치"가 있는가

이 프로젝트는 AutoCAD `Table`의 `CellBorder`에서 비슷한 것을 겪었습니다 —
값을 쓰는 것과 **그 값을 쓸지 말지(`Overrides`)가 따로**여서, 켜기 전에는 스타일이 이겼습니다.

`AxisTickStyle`에도 그런 것이 있습니까? 멤버 목록에는 안 보입니다.

## 7. 왜 코드로 해야 하는가 (템플릿으로 못 미루는 이유)

한동안 **템플릿(.dwt)에 사람이 넣는 것**으로 우회했습니다. 그런데 그럴 수 없는 이유가 생겼습니다.

이 애드인은 **주석 축척(Annotation Scale)을 일부러 안 바꿉니다.** 한 도면에 종단도(1:100)와 횡단도(1:150, 1:300…)가 **공존해야 하는데**, 주석 축척은 도면에 하나뿐이라 바꾸면 이미 그린 글자가 전부 흔들리기 때문입니다.

그 대가로 **스타일에 넣은 종이 크기가 축척마다 다르게 인쇄됩니다**:

```
종이에 나오는 크기 = 스타일 값 × 주석축척 ÷ 실제배치축척

주석 1:100, 횡단 1:150 → 12mm를 넣어도 종이에서 8mm
주석 1:100, 횡단 1:300 → 12mm를 넣어도 종이에서 4mm
```

그래서 **축척마다 스타일 값을 되돌려 계산해 넣어야** 합니다:

```csharp
스타일값 = 원하는종이크기 × 실제축척 ÷ 주석축척
// 12mm를 종이에 내려면 1:150에서는 18mm를 넣어야 한다
```

**글자 크기(`TextHeight`)와 눈금 크기(`Size`)는 이 방식으로 잘 동작합니다.** `OffsetX`만 안 되어서, 축척이 커지면 **글자만 커지고 간격은 그대로**라 눈금값이 눈금을 파고듭니다.

## 8. 여쭙고 싶은 것 (요약)

1. **`CenterAxis`의 `OffsetX`만 안 되는 이유가 무엇입니까?** 같은 코드로 `LeftAxis`는 됩니다. 중심축이 파생값이거나 다른 저장소를 쓰는 구조입니까?
2. **`Justification`이 `OffsetX`를 무효화합니까?** 순서나 조합에 규칙이 있습니까?
3. `AxisTickStyle`의 속성을 **중첩 접근으로 쓰면 안 되는** 것이 있습니까? 지역 변수나 `using`이 필요합니까?
4. **`OffsetY`를 써야 합니까?** 중심축은 세로축이라 축과 직각 방향이 `Y`일 수 있습니다.
5. `OffsetX`의 **단위**가 다른 속성과 다릅니까?
6. **UI에서는 되고 API에서는 안 되는** 알려진 사례입니까? 그렇다면 COM(`AeccGraphStyleCrossSection` 등)으로는 됩니까?
7. 축척마다 눈금값 간격을 조절하는 **다른 접근**이 있습니까? (예: 라벨 스타일 쪽, 또는 뷰별 재정의)
