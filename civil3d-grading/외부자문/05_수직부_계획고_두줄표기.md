# 자문 요청 — Civil 3D 종단 밴드에서 "수직부 계획고를 한 칸에 두 줄로"

작성: 2026-08-27 · DH.Grading (Civil 3D 2026 .NET 애드인, C#)

---

## 1. 무엇을 하려는가

부지 정지 설계에서 **옹벽·가시설 같은 수직 구조물**이 있는 구간의 종단면도 밴드 표기 문제입니다.

한국 2D 설계 도면 관례는 이렇습니다:

```
        No.5+12.34         ← 측점은 하나
계획고    184.10           ← 앞(진행방향 시작 쪽)
          189.10           ← 뒤
지반고    183.67           ← 하나뿐
절성토고   -0.43           ← 두 계획고에 각각 대응
          -5.43
```

- **수직부는 종단에서 측점 하나**만 쓰고, 그 칸에 **앞·뒤 두 숫자를 위아래로** 적는다
- **횡단면도에서는 (전)(후) 두 단면**으로 나눠 그린다
- **지반고는 하나** — 원지반은 수직이 아니므로

---

## 2. 근본 원인 (이건 확정)

**Civil 3D의 `Profile`은 한 측점에 표고를 하나만 가질 수 있습니다.** 수학의 함수처럼 생겨서 수직선을 담지 못합니다.

그런데 옹벽은 수직이라 한 자리에 표고가 둘입니다. 결과적으로 지금은 **벽 한복판을 뚫고 잰 중간값**이 밴드에 찍힙니다.

→ **데이터(Profile)로는 해결할 길이 없고, 표시하는 층에서 두 값을 보여 주는 수밖에 없다**고 판단했습니다. 이 판단이 맞는지도 함께 봐 주시면 좋겠습니다.

---

## 3. 시도한 방법

### 3.1 접근

1. 옹벽의 **앞·뒤 측점**은 이미 알고 있음 (`WallSpan(Mid, Front, Back)`)
   — 종단에 수직 막대를 그리려고 구해 둔 값
2. **계획 종단**(`Profile`)에서 그 두 자리의 표고를 읽음 (`pad.ElevationAt(front/back)`)
3. 그 측점의 **순정 밴드 글씨만 숨김** (`LabelGroupSubEntity.Visibility = false`)
4. 그 자리에 **`DBText` 두 개**를 위아래로 직접 그림

### 3.2 관련 API (실측으로 확인함)

```csharp
// 모형공간을 훑어 밴드 라벨 그룹을 찾는다
if (tr.GetObject(id, OpenMode.ForWrite) is CivilDb.LabelGroup lg
    && lg.GetType().Name.Contains("BandLabelGroup"))
{
    uint n = lg.SubEntityCount;
    for (uint i = 0; i < n; i++)
    {
        LabelGroupSubEntity se = lg.GetAt(i);
        Point3d loc = se.LabelLocation;     // [get/set]
        se.Visibility = false;              // [get/set]  ← 낱개로 끌 수 있다
        double rot = se.RotationAngle;      // [get/set]
    }
}
```

`LabelGroup`에는 `StyleName [get/set]`, `StyleId [get/set]`, `SubEntities`, `SubEntityCount`, `GetAt(uint)`가 있습니다.

### 3.3 막힌 지점 — **어느 라벨 그룹이 "계획고" 밴드인가**

`LabelGroup.StyleName`으로 고르려 했으나 **"계획"이 든 이름이 하나도 없었습니다**:

```
수직부 두 값 — 벽 7곳 · 계획고 라벨그룹 0개 · 숨긴 글씨 0개
              ⚠'계획'이 든 라벨 그룹이 없다
```

반면 **밴드 아이템** 쪽에서는 이름이 잘 읽힙니다. 횡단면도에서 같은 방식으로 밴드를 가려낸 적이 있습니다:

```csharp
using var items = sv.Bands.GetBottomBandItems();
var sb = tr.GetObject(items[i].BandStyleId, OpenMode.ForRead) as StyleBase;
// sb.Name → "DH_횡단 뷰_횡단 데이터_지반고", "…_계획고"  ← 이건 읽힌다
```

**즉 밴드 아이템의 스타일 이름은 읽히는데, 그 밴드가 만들어 낸 라벨 그룹의 `StyleName`은 다른 값**입니다(무엇인지 아직 확인 중).

### 3.4 현재 쓰고 있는 임시 방편

로그상 **밴드 라벨 그룹 수(6)와 밴드 칸 수(6)가 같으므로**, 라벨 그룹을 **평균 Y로 위→아래 정렬**하면 밴드 순서와 같다고 보고, 밴드 목록에서 찾은 계획고 순번으로 고릅니다.

```csharp
groupsY.Sort((a, b) => b.Y.CompareTo(a.Y));   // 위 → 아래
picks.Add(groupsY[planIdx].G);                 // planIdx = 계획고 밴드 순번
```

**이 가정이 위태롭다고 봅니다** — 밴드 하나가 라벨 그룹을 두 개 만들거나, 라벨이 없는 밴드가 있으면 순번이 어긋납니다.

## 4. 여쭙고 싶은 것

### ① 라벨 그룹과 밴드를 확실히 연결하는 방법

`LabelGroup`에서 **어느 밴드가 만든 것인지** 알아내는 정식 경로가 있습니까?
- `LabelGroup.StyleId`로 스타일을 열면 밴드 스타일과 대조할 수 있습니까?
- 아니면 `ProfileViewBandItem` 쪽에서 자기 라벨 그룹을 가리키는 속성이 있습니까?
- COM API(`AeccProfileViewBand` 등)에는 있는데 .NET에 없는 경우입니까?

### ② 더 나은 접근이 있는지

지금은 **순정 글씨를 끄고 우리가 `DBText`를 그리는** 방식입니다. 다른 길이 있을까요?

- **라벨 스타일의 표현식**으로 두 값을 한 라벨에 넣을 수 있습니까?
  (예: `<[단면1 표고]>` 아래에 다른 종단의 표고를 붙이는 식)
- **보조 종단(Profile)을 하나 더** 만들어 두고, 밴드가 그것을 참조하게 하면?
  즉 "옹벽 상단만 담은 종단"과 "하단만 담은 종단"을 각각 만들어 두 밴드로 표시
- 실무에서는 보통 **어떻게 처리**합니까? (수작업 편집이 일반적인지, 자동화 사례가 있는지)

### ③ 우리가 그린 글씨의 수명

`DBText`로 직접 그리면 **선형이나 측점이 바뀔 때 따라오지 않습니다.** 지금은 다시 그릴 때마다 그 레이어를 지우고 새로 그립니다.

- 라벨로 만들어 종단뷰에 붙이는 방법이 있습니까? (`ProfileViewLabel` 같은 것)
- 아니면 이 정도 수동성은 감수하는 것이 보통입니까?

### ④ 근본 판단이 맞는지

**"Profile은 한 측점에 표고 하나뿐이므로 데이터로는 못 푼다"** — 이 전제가 맞습니까?
혹시 수직 구간을 담는 다른 방법(예: 아주 짧은 수평 구간으로 근사, 별도 객체)이 실무에서 쓰입니까?
