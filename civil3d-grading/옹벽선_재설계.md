# 옹벽 재설계 — 옹벽선 정본화 + 띠 분할 방식 (2026-08-05 확정)

JACK 지시: **"단독으로 돌리든 이어서하든 둘 다 만족할 새로운 접근이 필요하다. 땜질식으로 하면 다른 경우의 수에
계속 막힌다. 지표면은 잘 만들어지는데 옹벽객체와 SHP 생성이 문제다."**

## 0. 왜 바꾸는가 — 현재 구조의 근본 결함

| 단계 | 현재 동작 |
|---|---|
| 정지면 생성(DHGRADE) | 계획선+설정 → 단 링 계산 → TIN 합성 → **지표면 완성(정상)**. 번들(계획선·설정·구간·최종링) 저장 |
| 내보내기(DHINFRA) | 번들로 **링을 처음부터 다시 계산** → 그 링 위에 옹벽·SHP 생성. 다중구역은 뒤 구역 발자국으로 **지우개** |

**결함의 뿌리는 "다시 계산"이다.** 지표면을 보고 만드는 게 아니라 같은 재료로 따로 만든다 —
재현과 실제가 조금이라도 어긋나면 전부 결함이 되고, 지우개 경계에서 조각이 남는다.
경우의 수를 하나 막으면 다른 게 튀어나오는 것이 구조적으로 당연하다(v17.5~v18.3이 그 반복이었다).

두 번째 결함은 **판넬 배치 방식**이다. 벽면마다 쪼개고 이웃 평면으로 서로 잘라내는(miter/ClipHalf/keep 부호)
기계장치가 복잡해 단독 케이스에서도 조각·각진부 마감 불량이 난다.
v17.6(라운드 벽면 소실) · v17.7(감긴 호길이) · v17.8(keep 부호 뒤집힘) · v18.2(프레임 비틀림)는
**전부 이 한 덩어리에서 나왔다.**

## 1. 확정 방향 (JACK 선택)

### ① 옹벽선 출처 = **정지면 만들 때 확정해 저장**
- 지표면을 만드는 **그 순간, 같은 계산 결과로** 옹벽선을 확정해 번들에 저장한다.
- 내보내기는 **저장된 선을 읽기만** 한다. 다시 계산하지 않는다.
- '이어서 하기'로 뒤 구역을 만들면 **그때 앞 구역의 저장된 옹벽선을 잘라 갱신**한다.
  → 저장된 선은 **항상 현재 최종 지표면과 일치**. 내보내기에 지우개가 없어진다.

### ② 판넬 배치 = **옹벽선 따라 띠를 만들고 길이방향으로 잘라 쓰기**
- 옹벽선(아랫선=토우, 윗선=크레스트)으로 **벽면 띠**를 하나 만들고, 길이방향으로 잘라 판넬로 쓴다.
- **판넬이 모서리를 가로지르지 않는다** → 이웃 평면 절단(miter/ClipHalf/keep 부호)이 **통째로 불필요**.
- 모서리는 띠 단계에서 **한 번만** 처리한다.

## 2. 자료 구조

```
WallRun                       // 옹벽선 한 줄 = 벽 한 폭
  bool  Up                    // true=절토 / false=성토
  int   Bench                 // 단 번호(0 = 1단)
  List<Point3> Toe            // 아랫선(3D)
  List<Point3> Crest          // 윗선(3D)  — Toe와 정규화 호길이로 1:1 대응
```

- Toe/Crest는 같은 링 쌍에서 나오므로 거의 평행(1:0.05·5m면 수평 0.25m 차이).
  대응은 **정규화 호길이**로 충분하다(별도 정점 짝짓기 불필요).
- 번들 **v9**: `WallRuns`(방향별 목록) 추가. v8 이하는 옛 경로(재계산)로 폴백해 기존 도면 보존.

## 3. 만드는 쪽 (DHGRADE)

1. 링이 확정된 직후(정규화·재주입 끝난 상태 — 번들 저장과 같은 시점), 방향별로:
2. 단 k가 **옹벽인 구간**을 구한다(전역 구배 ≤ MinSlope 이거나 SlopeZone 규칙이 수직).
3. 그 구간의 호길이 범위로 `rings[2k]`(크레스트)·`rings[2k-1]`(토우)를 잘라 `WallRun`을 만든다.
4. **최종링(데이라잇)으로 클립** — 실제로 정지가 일어난 범위만 남긴다.
5. **이어서 하기**: 새 구역 확정 시, 기존 구역들의 저장된 `WallRuns`를 **새 구역 발자국으로 잘라 다시 저장**.
   → 내보내기 시점에는 이미 최종 상태. `laterMask` 불필요.

## 4. 쓰는 쪽 (DHINFRA)

1. 모든 번들에서 `WallRuns`를 읽는다(재계산 없음).
2. 각 run마다:
   - **모서리에서 분할** — 진행 방향이 임계 이상 꺾이는 정점에서 run을 끊는다(판넬이 모서리를 안 넘음).
   - 끊긴 조각마다 길이 L, 열 수 `n = ceil(L/side)`, **열 폭 = L/n**(균등 분배 → 마지막 자투리 열 없음).
   - 열마다 토우·크레스트 두 점으로 사각 기둥면을 만들고, 세로로 `side`씩 나눠 판넬.
   - 데이라잇(원지반) 상한으로 클립.
   - 프레임 U(띠 진행 수평방향)·V(사면 상방)·W(법선) — **U는 수평이라 U⊥V가 자동**(v18.2 비틀림 원천 소멸).
3. 모서리 마감은 조각 끝을 두께/2만큼 연장(겹침)하는 **국소 처리 한 번**.

## 5. 폐기되는 것

- `keep` 필터(§75 구간 + 뒤 구역 마스크) — 옹벽선 자체가 이미 최종이라 불필요
- 코너 미터(`ClipHalf` 반평면 절단)·`keep` 부호·벽면 분할(`FindCornerIdx`)·감긴 호길이 되감기
- v18.2 프레임 직교화·v18.3 기울기 안전장치 — U가 수평이면 애초에 안 생김

## 6-1. P1 결과 (2026-08-05 완료) — 설계에 없던 것 2건 추가

구현하며 **설계에 빠져 있던 결함 2개**를 발견해 넣었다.

### ① 벽면이 어느 쪽을 보는가(W 부호) — 규칙 확립
판넬 노출면 방향을 안 정하면 벽이 뒤집혀(무늬·앵커가 흙 속으로) 나온다.
**평면에서 '크레스트 → 토우' 방향이 곧 노출면 방향**이고, 이는 절토·성토가 같다:
- 절토: 토우가 부지(파낸 쪽) 안, 크레스트가 산 쪽 → 노출면은 부지를 본다
- 성토: 크레스트가 부지 안, 토우가 바깥 → 노출면은 바깥을 본다

⇒ **절/성토 분기 없이 한 규칙.** (수평 거리 = 구배n×높이 = 1:0.05·5m면 0.25m로 잡음보다 충분히 큼.)
W와 어긋나면 U를 뒤집는다(`(−U)×V = −W` 라 오른손 좌표계 유지). 구간 방향·겹침도 함께 뒤집어야
데이라잇 보간이 어긋나지 않는다.

### ② 모서리 겹침 마감 (JACK '각진부 마감 이상')
두 벽면이 코너에서 정확히 만나면 볼록 모서리에 쐐기 틈이 남는다.
→ 벽면 **끝 열만** 모서리 쪽으로 `cornerLap`(기본 0.10m = 두께 절반) 더 내보낸다.
판넬은 자기 평면을 따라 나가므로 이웃 벽 뒤로 물려 코너가 꽉 찬다.
**※ 옛 방식의 '이웃 평면으로 잘라내기'와 달리 자르지 않는다** — 자르는 계산이 버그의 온상이었다.

### ③ '온전'(앵커 대상) 판정 — 첫 구현의 실제 결함
`열 폭 == 상한`으로 판정하면 **온전이 0장**이 되어 앵커가 통째로 사라진다
(균등 분배라 열 폭은 늘 상한보다 조금 작다: 1.553 < 1.667).
⇒ 온전 = **데이라잇에 안 잘린 완전한 사각 + 정착구(0.56m)를 물 만큼 큼(0.80m 이상)**.

### 어댑터
`WallBand.ToPanel(Tile)` → 기존 `WallPanels.Panel`. **DWG 작성기(솔리드·홈·도넛·앵커·정착판·무늬)를
그대로 재사용**한다 — 이미 현장 검증을 거친 코드라 새로 쓰면 그 검증을 처음부터 다시 해야 한다.
앵커 방향 = 벽 뒤(−W)에서 아래로 anchorDeg — W가 이미 노출면을 향하므로 절/성토 분기 불필요.

## 7. 원칙 (이 프로젝트에서 값비싸게 얻은 것)

- **가설은 오프라인 하네스로 판정한다** — Civil3D 왕복은 느리고 비결정적.
- **항상 통과하는 검사는 검사가 아니다** — 수정을 끄는 토글로 재발을 확인한다.
