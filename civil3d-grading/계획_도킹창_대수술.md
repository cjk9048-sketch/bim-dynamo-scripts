## 0. 1판이 왜 반려됐는가 — 먼저 적는다

검토 둘(기술·실무)이 **치명 다섯**을 냈고, **다섯 다 내가 코드로 직접 확인했다.**
1판은 *"자동으로 따라간다 · 겉이름만 가르면 된다"* 처럼 **재 보지 않고 단정한 문장**이 많았다.
그 문장들이 전부 틀렸다.

| 1판이 쓴 것 | 사실 | 확인한 자리 |
|---|---|---|
| 계획지표면 = `전체면_DH` | **`전체면_DH`는 터파기 자신의 산출물**(정지면+터파기). 목표면으로 쓰면 지난번 구덩이가 들어간다 | `ExcavCommand.cs:604-609` |
| 토적표는 자동으로 따라간다 | **`min` 규칙 사본이 셋.** 수량표는 터파기가 무슨 면을 썼는지 **모른다** | `StrataQuantity.cs:117`·`CrossSectionArea.cs:232`·`ExcavCommand.cs:205-267` |
| 되메우기 항목이 없다 | **이미 있다**(`back = shallow + deep`). 없는 게 아니라 **틀린 값으로 인쇄된다** | `CrossSectionArea.cs:248` |
| 방법이 다르면 나눠 돌린다 | **불가능.** 기록에 기준면 칸이 없고, 터파기는 **기록된 전부를 다시 만든다** | `ExcavBundleStore.cs:7-33`·`ExcavCommand.cs:272-278` |
| 가시설은 겉이름만 가르면 된다 | **이미 별개 개념으로 갈려 있다.** 옹벽으로 태그되면 종단 막대와 밴드가 **옹벽 규칙으로 그려진다** | `ProfileCommand.cs:2759·2775·2959`·`SheetCommand.cs:5501-5506` |

덤으로 **지금 깔린 코드의 버그 하나**를 찾아 이미 고쳤다 —
`PickMark`가 `EraseTransient`의 `bool`을 버리고 있었다. *"걷은 것만 해제한다"* 고
주석까지 써 놓고 **걷혔는지를 안 봤다**(오늘 아침 내가 넣은 방어다).

## 2. 터파기 기준면 — 다시 씀

### 2.1 절토부는 선택의 여지가 없다 (1판 그대로 · 유효)

절토부에서 원지반부터 재면 그 흙을 **부지 절토에서 한 번, 터파기에서 또 한 번** 센다.
그래서 갈리는 곳은 **성토부뿐**이다.

| 선택 | 뜻 | 절토부 | 성토부 | 쓸 면 |
|---|---|---|---|---|
| **계획지표면** | 계획고까지 성토·다짐 후 판다 | 계획면 | **계획면** | **`정지면_DH`** ← 1판 오류 정정 |
| **원지반** | 먼저 파고 구조물 세우고 나중 성토 | 계획면 | **원지반** | `min(계획, 원지반)` = 지금 그대로 |

`정지면_DH`가 맞는 이유: 코드가 스스로 *"이미 원지반+계획 합성면이다"* 라고 적어 뒀다
(`ExcavCommand.cs:606`). `전체면_DH`는 그 위에 **터파기까지 얹은 것**이라 쓰면 순환이 된다.
없으면 `ViewSurfaceCommand.PlanPick()`의 물러서기 규칙을 그대로 쓴다.

### 2.2 ★수량은 저절로 안 따라온다 — 이것이 이 수술의 진짜 일

```
ExcavCommand.cs:205~267    목표면 합성        ← 기준면을 아는 유일한 곳
StrataQuantity.cs:117      토적표 지표선      ← min을 혼자 다시 계산
CrossSectionArea.cs:232    횡단 면적·되메우기  ← min을 혼자 다시 계산
```

셋이 **서로 모른다.** 기준면만 바꾸면 굴착 형상은 내려가는데 수량표 지표선은
원지반에 머물러 **성토 두께만큼 터파기 물량이 조용히 빠진다.**
`deepLine = surf - 5`도 어긋나 5m 구분이 통째로 틀린 칸에 들어간다.

`StrataQuantity.cs:111-116`이 이미 적어 뒀다 —
*"두 계산이 서로 다른 지표면을 쓰면 합이 맞을 리가 없다 → 같은 것을 쓴다."*
**1판은 그 교훈을 정확히 되돌리는 계획이었다.**

→ **기준면을 `DH.Grading.Core`까지 인자로 흘린다.** 세 곳이 **한 값**을 본다.

### 2.3 되메우기 — "없다"가 아니라 "틀린다"

`CrossSectionArea.cs:248` `back = shallow + deep`. 이미 계산되고 표에 줄도 있다.
주석이 *"기준면을 터파기와 같은 자(낮은 쪽)로 맞춘다"* 고 적어 뒀으므로,
터파기만 계획면으로 올리면 **되메우기가 그 자리에서 어긋난다.**
→ **`back`도 같은 기준면을 쓰게** 한다. 2.2와 한 몸이다.

### 2.4 여전히 없는 것 — 밝혀 둔다

- **성토에서 구조물 부피 공제** — `CrossSectionArea.cs:247`이 *"구조물 형상이 모델에 없다"* 고 적어 뒀다. 레빗 투영 뒤 일.
- **흙막이(가시설) 면적** — 어디에도 없다(옹벽조차 물량 출력이 없다). 배수지에서 토공 다음으로 큰 항목이다. §8-C.

→ 토적표·로그에 **"미포함"으로 명시**한다. 조용히 빠지면 수량이 맞는 줄 안다.

### 2.5 기준면을 **도면에 기록**한다

`ExcavBundle`에 기준면 칸이 없고, `DoExcav`는 목표면을 **한 번** 합성해
**기록된 전부**를 그것으로 다시 만든다(`ExcavCommand.cs:272-278`).
A를 원지반으로 만든 뒤 B를 계획지표면으로 돌리면 **A가 말없이 바뀐다.**
이 저장소가 이미 겪은 사고와 같은 종류다(`ExcavBundleStore.cs:24-26`).

→ **`ExcavBundle.Base` 추가 · v3로 올린다**(v1→v2 이관 방식이 이미 있다).
목표면은 **기준면 값별로 나눠 합성**한다.
설정 저장도 레지스트리가 아니라 **도면 번들**이어야 한다 — 아니면 같은 DWG가 컴퓨터마다 다른 토적표를 낸다.

## 4. 도킹창에서 찍기 — **이미 도는 길을 쓴다**

1판은 `ExecuteInCommandContextAsync`를 새로 쓰자고 했다.
**그런데 이 저장소에 이미 도는 방식이 있다** — 지층 도킹창:

```csharp
// StrataPanel.cs:936
doc.SendStringToExecute("DHSTRATAPICK ", true, false, true);
// StrataDraw.cs:48
[CommandMethod("DHSTRATAPICK", CommandFlags.Modal)]
```

**이쪽을 쓴다.** 이유 셋 —
① **이름 있는 명령**이라 리본 활성/비활성이 쓰는 `CommandEnded`와 자연스럽게 맞물린다
(`ExecuteInCommandContextAsync`가 그 이벤트를 내는지 **확인 못 했다**).
② 예외가 명령 안에서 잡혀 **프로세스를 안 죽인다.**
③ `^C^C`·스크립트와 같은 규약을 탄다.
단점은 즉시가 아니라 **큐잉**이라는 것 — 도킹창 흐름에서는 문제가 안 된다.

```
[계획 경계 선택] → SendStringToExecute("DHPICKPLAN ")
      DHPICKPLAN : GetEntity → 핸들 보관 → 빨갛게 → 창 갱신
[원지반 선택]   → "DHPICKGROUND "
[지표면 생성]   → "DHGRADEBUILD "   (보관한 핸들로)
```

**★`ObjectId`가 아니라 `Handle`을 보관한다** — 이 저장소가 이미 그 방식이다
(`GradingSettings.LastPlanHandle` + `NoriCommand.FindByHandle`, `IsErased`까지 본다).
되돌리기로 지웠다 살렸다 해도 안전하다.

**막아야 할 것**
- **찍기 잠금은 두 창이 하나를 공유한다**(창마다 두면 §50 함정). 찍는 동안 관련 리본 항목도 회색.
- **도면 전환** — `DocumentToBeDeactivated`에서 걷는다. `DocumentActivated`는 **이미 넘어간 뒤**라 늦다.
  걷을 때 **그 도면이 맞는지 확인**하고, 아니면 **아무것도 안 하고 버린다**.
- **`SyncToDocument`를 팔레트가 부른다** — 지금은 명령 진입 때만 부른다. 창이 UI가 되면 아무도 안 불러
  **앞 도면 값을 보여주고 그 값을 새 도면에 밀어 넣는다.**
- **PickMark 걷는 자리**: 만들기 성공/실패 · 다시 찍기 · **도면 전환 직전** · 팔레트 `StateChanged`(자동숨김·닫기) · 도면 닫기 · 레이아웃 전환.
- **`SaveUserPrefs()` 금지** — `SaveUserPrefInt`만. 그리고 팝업의 `_miterAtOpen` 가드는
  *"창을 연 순간"* 이 있어야 성립하는데 **늘 떠 있는 창에는 그 순간이 없다** — 다른 방법이 필요하다.

## 5. 두 창

### 5.1 계획부지 정지 창

1판 그림 그대로. 단 **두 가지 추가**:

- **`○ 이어서 / ○ 새로시작`** 칸이 있어야 한다. 지금 명령은 계획선을 찍은 뒤 이걸 묻고,
  그 답에 따라 **원지반을 아예 안 묻는다**(`CreateGradingCommand.cs:105-149`).
  1판의 *"둘 다 골라야 [생성]이 켜짐"* 은 지금 동작과 모순이었다.
  ★판정은 **[생성]을 누르는 순간 다시** 한다 — 그 사이에 초기화·사면수정이 끼면 뒤집힌다.
- **예시 그림**은 420×300 둘을 **세로로 쌓고 창 폭에 맞춰 다시 그린다.**

### 5.2 구조물 터파기 창 — 보기와 기준면을 가른다

```
① 터파기 기준면        ○ 계획지표면   ○ 원지반      [이 면 보기]
② 대상                 [터파기선 선택]  [ 생성 ]
③ 굴착                 구배 1:[  ]   사면형상 ● 직각
```

**보기를 라디오에서 떼어낸 이유.** `ViewSurfaceCommand.Apply()`는 화면만 바꾸는 게 아니다 —
끈 레이어를 **도면에 저장**하고(`DH_GRADING/VIEW_OFF`), `VSCURRENT`를 전역으로 바꾸고,
`RebuildAllSurfaces` 없이 숨겨 **느낌표를 되살릴 수 있다**(v32.4~32.7이 잡았던 것).
게다가 `Apply("G")`는 `DH-` 레이어를 전부 꺼 **터파기 결과까지 사라진다.**
라디오를 옮길 때마다 이게 돌면 안 된다. JACK 지시(*"고르면 그 지표면만 뜬다"*)는
**단추 한 번**으로 충족된다. 팔레트 닫기·도면 전환에서 `ShowAll()`을 부른다.

### 5.3 ★가시설 — 겉이름 문제가 아니었다

**이 저장소는 옹벽과 가시설을 이미 갈라 놓았다.**

| | 옹벽 | 가시설 |
|---|---|---|
| 종단 막대 레이어 | `DH-종단-옹벽`(시안) | `DH-종단-가시설`(마젠타) |
| 막대 위/아래 | 계획면 ↔ **원지반** | 계획면 ↔ **터파기 바닥** |
| 종단 밴드 | 계획고·절토고·성토고 **두 값** | **건너뜀 — 한 값** |
| 판정 | `Kind.Contains("가시설")` 문자열 매칭 | |

`SheetCommand.cs:5118`에 JACK 말씀이 박혀 있다 —
*"터파기는 복구할 거라 계획고에 포함이 안 돼. 가시설 수직부는 계획고로 나타내면 되고 옹벽부만 적용하면 돼."*

**그래서 1판대로 옹벽 경로를 재사용하면** `Kind="옹벽"`이 되어
종단에 **시안 막대가 계획면↔원지반으로** 그려지고(바닥까지 안 내려감),
밴드가 **두 값으로** 찍힌다 — JACK이 명시적으로 금지한 것.

**게다가 [가시설 변환] 단추는 무동작이 된다.** 구간별 가시설이라는 개념이 데이터에 없다:

| 막히는 곳 | 상태 |
|---|---|
| `ExcavCommand.cs:348` `Build(..., up:true, **null**)` | 벽 구간을 **안 넘긴다**(바로 위 `:233`은 넘긴다) |
| `ExcavBundleStore` | 구간 칸 없음 |
| `StationMarks.cs:819` `e.Slope <= WallGateSlope` | **레코드 전체**가 가시설이거나 아니거나 |

세 곳을 다 고쳐야 단추가 일을 한다. 크기: 수직/사면 지정 하나가 **토공 4,900㎥**를 움직인 실측이 있다
